# Targeted push and amend publication
1. Require an attached branch and a concrete remote plus remote branch. Prefer its verified upstream; do not assume origin/main. If no upstream/target exists, ask or accept `--remote NAME --branch NAME`. Reject option-like refnames or embedded refspec syntax; use explicit source/destination refs and validate branch syntax.
2. Inspect committed range, outgoing changes and remote tip. Ordinary gitpush may send several commits; make that range visible and do not silently omit it. Respect project validation gates and protected branches. Never publish private backup refs, tags or unrelated branches with --all/--mirror.
3. Ordinary gitpush only uses fast-forward push. On divergence, report and stop; no implicit pull, merge, rebase, reset or force.
4. For gitpushamend, perform all remote/protection/history checks BEFORE amending. Let H be old local HEAD and R the verified remote tip. If R=H, amending rewrites a published tip. If R is an ancestor of H and H is not published on that destination, amending H can normally be followed by fast-forward push. If R contains descendants of H or is divergent, stop: do not treat a freshly fetched tip as permission to delete others' commits. If reachability cannot be determined, obtain the relevant objects or pause. Other known publication destinations must also be reported.
5. A requested gitpushamend authorizes its documented targeted rewrite on a permitted branch; do not ask redundantly when scope is concrete. If branch protection/shared-branch policy forbids or needs approval, obey it and present the concrete blocker before amendment.
6. Pin the inspected destination SHA R. If rewrite is necessary, use only `--force-with-lease=refs/heads/<branch>:<R>` and explicit `<new-head>:refs/heads/<branch>`. A bare --force-with-lease that relies on mutable tracking refs is insufficient. Do not refresh R and blindly retry after a rejected lease. Reinspect and report new remote commits.
7. If no remote branch exists, normal push creation is allowed only for the user's verified target. Check upstream-setting intent; no automatic switch to another remote. After success verify the target points to the intended commit. Report uncertainty if final verification is unavailable.
8. An amend changes commit identity even with --no-edit. Never amend again just because push failed. Keep the new local commit and recovery ref; retry only the publication step when authorized. Preserve authorship and message; never add co-author trailers or reset-author unless asked.
