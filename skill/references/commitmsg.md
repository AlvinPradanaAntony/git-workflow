# commitmsg

Read `references/common.md` before acting. Follow the user's explicit scope and this command's mutation boundary.

Read `references/messages.md`. Accept its message options, `--source auto|staged|unstaged|all`, `--all`, and `--files <paths...>`. Selectors conflict unless equivalent; reject `--source description` for execution and offer commitpln. Descriptive text supplies context, never substitutes for the diff.
Format selection when `--format` is omitted: inspect repository status and count unique changed paths across the index, working tree and all nonignored untracked files. Count a path once even if it has staged and unstaged hunks. If exactly one repository path is changed and the selected commit diff contains that path as one coherent change, use `short`; otherwise use `standard`. Do not count only staged files while overlooking other working-tree changes. Never widen the commit selection to make this rule apply. An explicit `--format short|standard|detailed` overrides the automatic choice. Keep required issue/breaking trailers and the EN/ID separator even when the result is short. Do not compress unrelated changes in one file into a misleading subject; apply the grouping rule below first.
1. With no selector (auto), commit EXACT current staged diff if nonempty. Keep all unstaged hunks intact; do not restage partially staged files. If that staged selection contains unrelated purposes, show a commitpln grouping and ask which group/order to use instead of bundling automatically.
2. If auto finds no staged changes, inspect unstaged plus eligible untracked files. When a single coherent task is clear, announce exact selected files, stage them with explicit literal paths and commit without another routine approval. If multiple tasks/ambiguous files exist, provide a concrete plan and ask for selection. Avoid auto-including sensitive files, ignored output or unrelated artifacts.
3. `--all` explicitly selects the working-tree versions of all nonignored changes, including tracked deletions and eligible new files. Explain that this includes formerly unstaged hunks; do not claim partial staging is preserved under this explicit whole-change selection. Still stop for secrets, unresolved conflicts or ambiguity about grouping.
4. `--files` selects only listed paths. If other staged paths exist, do not unstage them or accidentally commit them: show the conflict and ask for a scoped staging choice. If a selected file has staged AND unstaged changes, preserve existing staged hunks by default and ask before replacing them with the whole file. A directory selector requires listing expanded paths first. Reject paths outside the repository.
5. `--source staged` requires a nonempty staged diff and never falls back. `--source unstaged` can stage a coherent selection only when no preexisting staged content would be included; otherwise ask for isolation instead of silently committing both.
6. After staging, reread repository status and the exact cached diff, apply the format rule above to the current paths and build the message. Check that the subject summarizes every related material change and each `- ` bullet adds information instead of repeating the subject or another bullet. If unrelated changes cannot be represented by one honest subject, show a `commitpln` grouping and ask which group/order to use. Run only required relevant repo validation; report actual results. Never create an empty commit. For unborn HEAD use cached diff against the empty tree without assuming HEAD exists.
7. Verify selection/HEAD again, commit from an exact message file, inspect resulting commit message and patch, and report short hash plus remaining work and no push. If hooks fail, stop and report; no skip or destructive rollback. Commitpln is the only preview command; an explicit preview-only user request always overrides execution.
